# Run Stripe-native subscriptions

Stripe owns the billing clock, renewals and retry schedule for this provider's subscription implementation. Use `@antelopejs/interface-subscriptions` in the consumer module; Stripe-native subscriptions are the recommended choice when Stripe takes the payments.

## Create and receive events

Use a customer and payment method saved through an on-session payment. This complete function creates a monthly subscription on the selected account; persist and reuse its key for retries, and store the returned ID.

```typescript [subscriptions.ts] docs-check
import { CreateSubscription } from "@antelopejs/interface-subscriptions";

export async function subscribeMonthly(
  customer: string,
  paymentMethod: string,
  reference: string,
  idempotencyKey: string,
  provider?: string,
) {
  return CreateSubscription(
    {
      customer,
      paymentMethod,
      reference,
      amount: { value: 2500, currency: "EUR" },
      interval: "month",
    },
    idempotencyKey,
    provider,
  );
}
```

Without a trial or future billing anchor, creation charges the first period with `payment_behavior: "error_if_incomplete"`. A declined first charge creates no subscription and raises `SubscriptionPaymentError`; Stripe voids that attempt, so the attached payment reports `canceled`, with the decline code in `providerCode`.

Register `SubscriptionEvents` handlers in the consumer module and route the four subscription event types through [portable `VerifyWebhook`](./3.webhooks.md). It awaits every registered handler. Deduplicate effects by event ID and propagate processing failures so Stripe can retry. Subscription-only deliveries return no payment event.

## Ownership and product

The provider creates or reuses the fixed product ID `antelopejs_subscriptions` in each account and creates recurring prices beneath it. Keep that product available; do not archive it.

Ownership is the presence of reserved metadata key `antelope_reference`, written when this interface creates a subscription. Subscriptions created elsewhere through Checkout, the dashboard or `GetClient()` without that marker are excluded from reads, lists, mutations and events. Their payments receive no `antelopeSubscription` marker. Preserve the ownership metadata, and do not add it to unrelated subscriptions to bypass this boundary.

`GetPayment` and payment webhooks use Stripe's invoice-payment relationship to mark owned subscription charges with `metadata.antelopeSubscription`. This requires an additional read with the basil API model, where PaymentIntents no longer directly expose the invoice.

## Status and retry ownership

| Stripe status                                | Interface status |
| -------------------------------------------- | ---------------- |
| `trialing`, `active`, `past_due`, `canceled` | Same name.       |
| `unpaid`, `paused`, `incomplete`             | `past_due`       |
| `incomplete_expired`                         | `canceled`       |

`vendorData.status` preserves the raw Stripe status and `vendorData.collectionMethod` preserves the collection method. Stripe dashboard settings determine what happens after `past_due`; configure cancellation when retries are exhausted. Stripe does not charge an `unpaid` subscription again, so leaving it unpaid can leave the normalized state `past_due` indefinitely.

`UpdateSubscriptionPaymentMethod` changes the method for the next scheduled attempt; it does not immediately charge. The provider exposes epoch milliseconds but Stripe stores times to the second, so trial and billing-anchor inputs lose sub-second precision.

## Cancellation and end semantics

`CancelSubscription(id, key, "period_end", provider)` sets `cancelAtPeriodEnd` and leaves the subscription running until its paid period ends. `"now"` ends it immediately. An ended subscription reports `endedAt` from Stripe's `ended_at`, then `canceled_at`, with creation time as a fallback. It reports `endReason: "payment_failed"` only for Stripe's cancellation reason `payment_failed`; other ended subscriptions report `"requested"`.

Immediate cancellation is a DELETE, so Stripe's POST idempotency retention does not apply. The provider writes `antelopejs-idempotency-key:<key>` into the cancellation comment and recognizes a retained matching marker on replay. Preserve the comment if you rely on this recovery path. Creation, period-end cancellation and payment-method updates use Stripe POST idempotency, retained for at least 24 hours; reconcile uncertain outcomes beyond that window as described in [retry safety](./2.payments.md#idempotency-and-uncertain-outcomes). No indefinite replay guarantee applies.

## Choose the generic scheduler explicitly

Use `@antelopejs/payment-subscriptions` only when you deliberately want the generic payment-interface scheduler instead of Stripe's billing clock. Add that module to the project and set `disabledExports: ["@antelopejs/interface-subscriptions"]` on this provider's module entry (beside `source` and `config`). Keep the provider's payment export enabled so the generic scheduler can charge through it.

The following configuration selects the fallback modules. Merge these entries into a project that already provides the generic scheduler's required database interface; this is not a standalone runnable database setup. Build both coordinated checkouts first and supply the two environment overrides before startup.

```typescript [antelope.config.ts] docs-check
import { defineConfig } from "@antelopejs/interface-core/config";

export default defineConfig({
  name: "generic-billing-project",
  modules: {
    stripe: {
      source: { type: "local", path: "../stripe" },
      disabledExports: ["@antelopejs/interface-subscriptions"],
      config: {
        apiKey: "REPLACE_VIA_ENV",
        webhookSecret: "REPLACE_VIA_ENV",
      },
    },
    subscriptions: {
      source: { type: "local", path: "../payment-subscriptions" },
    },
  },
  envOverrides: {
    STRIPE_SECRET_KEY: "modules.stripe.config.apiKey",
    STRIPE_WEBHOOK_SECRET: "modules.stripe.config.webhookSecret",
  },
});
```

Consult the [generic scheduler documentation](https://github.com/AntelopeJS/payment-subscriptions/tree/main/docs) for its storage and lifecycle requirements. This choice changes billing ownership; it does not migrate existing Stripe-native subscriptions. Keep a single scheduler responsible for each subscription.
