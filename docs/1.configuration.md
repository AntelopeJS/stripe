# Configure the Stripe provider

The provider needs a default Stripe account and a signing secret for its webhook endpoint. Keep credentials in the environment; configuration files contain placeholders only.

## Local coordinated checkout

Build this provider and its coordinated interface checkouts before starting your project. This complete configuration assumes the project sits beside a `stripe` checkout; adjust `path` to your layout. Consumer modules still declare their interface dependencies and must resolve the coordinated interface versions.

```typescript [antelope.config.ts] docs-check
import { defineConfig } from "@antelopejs/interface-core/config";

export default defineConfig({
  name: "my-project",
  modules: {
    stripe: {
      source: { type: "local", path: "../stripe" },
      config: {
        apiKey: "REPLACE_VIA_ENV",
        webhookSecret: "REPLACE_VIA_ENV",
        endpoint: "stripe",
        maxNetworkRetries: 2,
        accounts: {
          europe: {
            apiKey: "REPLACE_VIA_ENV",
            webhookSecret: "REPLACE_VIA_ENV",
          },
        },
      },
    },
  },
  envOverrides: {
    STRIPE_SECRET_KEY: "modules.stripe.config.apiKey",
    STRIPE_WEBHOOK_SECRET: "modules.stripe.config.webhookSecret",
    STRIPE_EU_SECRET_KEY: "modules.stripe.config.accounts.europe.apiKey",
    STRIPE_EU_WEBHOOK_SECRET:
      "modules.stripe.config.accounts.europe.webhookSecret",
  },
});
```

Supply all four environment variables through your local secret manager or deployment environment before startup. Use each endpoint's own signing secret, not the API key or a secret from a different Stripe endpoint. Remove the `europe` account and its overrides if you only need the default account.

For registry installations after compatible publication, replace the local source with `{ type: "package", package: "@antelopejs/stripe", version: "<compatible published version>" }`. The CLI writes credential placeholders; environment overrides must replace them before startup.

## Configuration keys

| Key             | Meaning                                                                                                    |
| --------------- | ---------------------------------------------------------------------------------------------------------- |
| `apiKey`        | Secret API key for the default account.                                                                    |
| `webhookSecret` | Signing secret for the default account's endpoint.                                                         |
| `endpoint`      | Built-in legacy route path, default `stripe` (`POST /stripe`). It does not mount a portable webhook route. |
| `accounts`      | Additional named accounts, each with `apiKey` and `webhookSecret`.                                         |
| Other keys      | Shared Stripe SDK options such as `apiVersion`, `maxNetworkRetries` and `timeout`.                         |

The trailing `provider` argument on payment and subscription calls selects an account name such as `"europe"`. Omit it for the top-level default account. Keep the same selector for creation, reads, mutations and webhook verification; IDs from one account cannot be read in another. An unknown selector rejects rather than falling back to the default account.

This selector chooses a configured Stripe account, not an arbitrary provider implementation or Stripe Connect account header. The legacy `GetClient()` and built-in endpoint always use the default account.

## Optional integrations

- A module implementing `@antelopejs/interface-api` mounts the [legacy built-in webhook route](./5.legacy-stripe.md). Without it, the provider logs a warning and continues. Portable consumers mount their own route and call `VerifyWebhook` regardless.
- A module implementing `@antelopejs/interface-redis` enables cross-instance legacy PaymentIntent watcher notifications. Without it, watchers receive local built-in endpoint deliveries only. Portable webhook processing does not require Redis.

The [README compatibility tables](../README.md#compatibility) track the manifest's exact interface ranges. No other payment provider implementation is promised by this configuration.
