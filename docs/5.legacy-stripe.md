The provider also implements the Stripe-specific `@antelopejs/interface-stripe` API. Use it for Stripe SDK operations, client-secret flows, and PaymentIntent watchers. Portable consumers do not need it.

## Initialize and watch a payment

Install `@antelopejs/interface-stripe` in the consumer module. Call the following function inside AntelopeJS after the provider starts. Send the client secret only to the payer, who confirms the payment with Stripe.js.

```typescript [legacy-payment.ts] docs-check
import { InitializePayment, WatchPayment } from "@antelopejs/interface-stripe";

export async function initializeOrder42() {
  const intent = await InitializePayment("order-42", {
    amount: 2500,
    currency: "eur",
    payment_method_types: ["card"],
  });

  WatchPayment(intent.id, (id, paymentIntent, context) => {
    console.log(id, paymentIntent.status, context.local);
  });

  return { paymentId: intent.id, clientSecret: intent.client_secret };
}
```

`GetClient()` returns the SDK client of the default account. The [interface reference](https://interfaces.antelopejs.com/docs/stripe/introduction) describes `WaitForPayment`, `WatchAllPayments`, `WatchPayment`, and `CompletePayment`. The payload metadata and the SDK objects of this API are not the `reference` and the normalized events of the portable payment interface.

## Built-in webhook route

When a module implements the optional API interface, the provider mounts `POST /stripe`, or the path set in `endpoint`. Point the Stripe endpoint of the default account there, and enable the `payment_intent.*` events that your watchers need. To complete payments from Stripe sources, also enable `source.chargeable`.

The route reads the `@RawBody()` bytes and the `stripe-signature` header, verifies them with the default `webhookSecret`, and answers `403` when verification fails. A verified PaymentIntent emits to local watchers with `context.local: true`. Optional Redis relays the signed delivery to the other instances. Each one verifies it with its own default `webhookSecret`, then emits the PaymentIntent with `context.local: false`, so every instance needs the same default account. A message on the channel that is not a delivery this account signed is dropped. Redis is not required for local-only watching.

The built-in route does not call portable `VerifyWebhook`, does not return normalized payment events, and does not call `SubscriptionEvents` handlers. When you use the payment or subscriptions interfaces, configure a separate [portable webhook route](./3.webhooks.md). Named accounts apply only to portable calls. The built-in route always uses the default account.
