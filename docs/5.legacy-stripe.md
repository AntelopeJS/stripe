# Keep the Stripe-specific integration

The existing `@antelopejs/interface-stripe` API remains available. Use it for Stripe SDK operations, client-secret flows and existing PaymentIntent watchers; portable consumers do not need to adopt it.

## Initialize and watch a payment

Install `@antelopejs/interface-stripe` in the consumer module. Call this function inside AntelopeJS after the provider starts, and send the client secret only to the intended payer for Stripe.js confirmation.

```typescript [legacy-payment.ts] docs-check
import { InitializePayment, WatchPayment } from "@antelopejs/interface-stripe";

export async function initializeOrder42() {
  const intent = await InitializePayment("order-42", {
    amount: 2500,
    currency: "eur",
    payment_method_types: ["card"],
  });

  WatchPayment(intent.id, (id, paymentIntent, context) => {
    console.log(id, paymentIntent.status, context.local);
  });

  return { paymentId: intent.id, clientSecret: intent.client_secret };
}
```

`GetClient()` returns the default account's SDK client. `WaitForPayment`, `WatchAllPayments`, `WatchPayment` and `CompletePayment` retain their Stripe-specific contracts; see the [interface reference](https://interfaces.antelopejs.com/docs/stripe/introduction). The legacy payload metadata and SDK objects are not the portable payment interface's `reference` and normalized events.

## Built-in webhook route

A module implementing the optional API interface mounts `POST /stripe` by default, or the path configured in `endpoint`. Point the default account's Stripe endpoint there and enable the `payment_intent.*` events your watchers need. For legacy source-based completion, also enable `source.chargeable`.

The route reads `@RawBody()` bytes and the `stripe-signature` header, verifies them with the default `webhookSecret` and answers `403` when verification fails. A verified PaymentIntent emits to local watchers with `context.local: true`. Optional Redis relays the signed delivery to the other instances. Each one verifies it with its own default `webhookSecret`, then emits the PaymentIntent with `context.local: false`, so every instance needs the same default account. A message on the channel that is not a delivery this account signed is dropped. Redis is not required for local-only watching.

The built-in route does not call portable `VerifyWebhook`, return normalized payment events or invoke `SubscriptionEvents` handlers. Configure a separate [portable webhook route](./3.webhooks.md) when you use payment or native-subscription interfaces. Additional named accounts apply to portable calls only, not this built-in default-account route.
